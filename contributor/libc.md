# libc

用 Rust 实现的 C 标准库。README 面向使用者；本文件记录实现取舍与改动前需要知道的约定。

## errno 的两层局部性

C 标准要求 errno 线程相关。落地方式：每个经本库引导的线程持有一个用户态控制块（errno 槽在
偏移 0），线程引导把 FS 段基址设为控制块地址，内核调度器按线程保存恢复基址。取 errno 时读
当前 FS 基址：非零即指向本线程的槽；为零（线程未经引导）退回进程级后备槽——对单执行上下文
的进程语义正确。诚实边界：未引导的线程共享后备槽，这是能力边界不是缺陷。

## 与 csrc 的关系

csrc 是独立式 C 运行环境（自由式、无标准库），本库是带 C 接口的标准库实现。两者服务不同场景：
csrc 的极简构建路径不需要本库；要标准接口的 C 程序用本库。libccheck 命令验证的是本库，csrc 的
示例程序验证的是 csrc，两个验收链路不混用。

## 测试的分布

库内单元测试贴着实现（19 个）；test_harness 是独立的宿主机测试程序（64 个测试函数），专门覆盖
格式化引擎的边界——浮点全范围往返、strtol 溢出与进制探测、qsort 与 bsearch 的退化输入。格式
引擎的改动先跑 harness 再跑库内测试。

## 无缓冲文件流

文件流默认直接读写底层，没有用户态缓冲。这是有意的：系统的读路径自带页缓存，再叠一层用户态
缓冲只会引入一致性负担。性能敏感的程序自己组块。
