# sdk

面向第三方的开发工具集（规划中）。README 面向使用者；本文件记录规划取舍。

## 为什么仓库现在是空的

内容尚未落地，所以不假装它已经存在——这是刻意的纪律。在内容真正可用之前，本目录不被任何脚本
引用、不承载任何构建产物。空壳仓库让外部开发者下载之后发现什么都没有，比暂时不提供更糟。
README 里的每一项计划都以「未开始」标注，状态变化时先改 README。

## 与 tools 的分界

旧 `sdk/` 目录实际做的全是系统自身的构建与验收，名字却承诺了第三方工具；2026 年 10 月改名
`tools/`，本仓库承接「给第三方的东西」这一承诺。划分规则一句话：第三方开发者要用到的才进本
仓库。第三方程序的构建进数据盘的流程留在 tools——那一步服务的是系统验收。

## 目标定义里两个关键点的来源

- 关闭位置无关：内核加载器不做地址重排，程序按链接脚本固定布局加载。
- 显式声明线程局部存储：编译器默认的 TLS 模型假设动态链接器，本系统的用户态程序不经过它。

这两点在现有用户态程序的构建里都是手工指定的，工具集要做的是把它们固化进目标定义，让用户
不必知道。
