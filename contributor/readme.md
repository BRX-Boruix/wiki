# README 规约

本文件规定 BORUIX 各仓库 README 的内容范围与书写格式。

## 文件

每个仓库有两个 README：

- `README.md` —— 中文
- `README.en.md` —— 英文

两者在顶部互相链接。

## 内容判据

README 收录**面向公众**的内容：如何使用这个程序、它的行为与限制。

下列内容不写入 README，改写进 [wiki](../) 的 `contributor/<仓库名>.md`：

- 实现细节与设计取舍
- 代码组织与模块划分的理由
- 修改这部分代码时需要知道的约定与陷阱

判定方法：某一节的内容，**只有读过源码或参与开发的人才需要**，就不属于 README。

## 结构

```
# <仓库名>

<一句话说明它是什么、解决什么问题>

[English](README.en.md)

## <功能 / 用法 / 测什么>
## 已知限制
## 构建
## 仓库布局
## 相关项目
## 许可
```

各节按仓库性质取用。库与驱动写「功能」，验收程序写「测什么」，守护进程写「它做什么」。

`已知限制`与`仓库布局`可以省略。

## 格式

### 不使用表格

README 中不使用表格，需要列举时用 `-` 列表。

### 首句直述

第一句直接说明这个仓库是什么，不使用引导性的话。

### 列举只保留必要项

列表不罗列由仓库性质即可推知的条目。行编辑库列举「输入、退格、删除」没有信息量；列举
「回显抑制，用于口令输入」才有。

### 仓库布局用列表

`仓库布局`一节用 `-` 列表，只列目录与关键文件，同类文件合并为一行。

```
- `src/lib.rs` —— 模块导出
- `src/io.rs`、`mem.rs`、`process.rs` —— 各领域接口
```

### 只陈述事实

写「最多尝试 3 次」「不区分用户不存在与口令错误」。

不写「这样设计是因为……」「这一步很重要」。

## 用词

只使用读者能查证的名词：真实的函数名、真实的路径、程序真实输出的字符串、通行术语。

不使用仅为内部使用的编号、代号与文档名。

## 长度

不设字数上限。按内容判据取舍后剩余多少即为合适长度。

作为参考，纯程序仓库通常在 800–1500 字符；含格式规范或完整构建说明的库会更长。

## 许可

每个仓库一份 MIT `LICENSE`，内容为 `Copyright (c) 2026 Yang Borui`。

由外部项目衍生的仓库保留其原有许可。

## 完成标准

- [ ] 文档中的数字与行为均核对过源码
- [ ] 无表格、无内部编号
- [ ] 中文与英文两份内容一致
