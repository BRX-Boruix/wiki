# csrc

独立式 C 运行环境。README 面向使用者；本文件记录运行时设计与构建脚本的约定。

## 与 Rust 侧的独立性

C 程序走自己的启动代码，不经过 Rust 的入口体系；两者直接与同一个内核接口对话。这是刻意的：
跨语言依赖会让两个运行时的改动互相牵制。改动系统调用约定时，两侧同步改，无共享代码可依托。

## 链接器的探测

构建脚本优先用 clang 附带的 ld.lld。本机曾出现终端安全产品间歇性拒绝执行它、而同目录 clang
正常的情况——这是环境故障不是工具链问题，但它会让每次 C 链接都失败且无可用诊断。脚本改为
探测：候选包括 clang 的 ld.lld 与 Rust 工具链自带的 rust-lld（同是 LLD，需加 `-flavor gnu`），
逐一试运行取可用者，并把选择打印出来。探测优于写死路径。

工具链目录从 RUSTUP_HOME 找，不是 CARGO_HOME（后者只有注册表与 bin）。曾因读错变量得到空候选
列表，两个环境变量都查，另备固定路径兜底。

## 线程边界的来源

- 返回值只支持整数：内核回收线程时只携带退出码，描述符传值是运行时补的层。
- join 只能由组长调用：内核回收机制的限制。示例程序按此约束编写。
- 同步对象用完整类型：让程序可以声明全局或栈变量；对象内部同时持有用户态状态与内核同步字，
  这是「用户态快速路径加内核阻塞」的组合，改结构前先看 pthread_sync 的实现注释。

## 构建的单翻译单元约束

脚本假定目标程序是单个 .c 文件（单翻译单元）。多文件程序把其余 .c 作为额外的运行时源传入，
它们会被编译并与运行时一起链接。这个约束简化了脚本，当前所有示例与自检程序都符合。

## 位置无关与栈

编译固定 `-fno-pic`，链接固定 `-z noexecstack` 与本仓库的链接脚本。段布局由 `linker.ld` 决定，
内核按该布局加载。改链接脚本前先核对内核加载器的假设。
