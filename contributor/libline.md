# libline（维护者说明）

## 为何存在

同一能力在仓库里曾实现**两遍**：

- `shell/src/main.rs:298` 完整版（125 行：history / Tab 补全 / CSI 光标编辑 / 重绘）；
- `login/src/main.rs:186` 朴素版（仅退格 erase）。

本库把它们收敛为**一份**，并同时为口令回显抑制提供了唯一正确落点。

## 为何拆成两层

行编辑有两类关注点，**可测性天差地别**：

- **编辑语义**：光标移动后缓冲区长什么样、退格删哪个字符、历史怎么翻页。**纯函数**，可宿主测试。
- **渲染**：发什么字节给终端、何时重绘。需要终端，只能在 QEMU 里看。

`editor.rs` 只做第 1 类：把 `InputItem` 序列变成缓冲区状态变迁。渲染通过 `EditorHost` trait 由
调用方提供，故编辑器本身可在宿主上用**假 host** 驱动，断言缓冲区与渲染调用序列。

## 输入源是窄接口

本库只依赖一个「取下一个输入单元」的窄接口（`InputSource`），**由调用方决定其背后是字节流还是
事件流**。

当前按**字节流**先行落地；事件流落地时，只需提供另一个 `InputSource` 实现，**编辑器本体一行
不改**。

### 用法契约（实测踩过）

`EventSource` 的两条用法，本库初版都违反了，真机表现为「open 成功但毫无反应」：

1. **`next_item()` 不是入口**——缓冲空时立即返回 `WouldBlock`，取数由 `refill()` 负责；
2. **`refill() == false` 不是 EOF**，只表示本轮无新字节。权威用法见 `editor.rs:471-475`：

```rust
if refill() { continue; }
yield_now();
continue;      // 绝不 break
```

## 边界

**不是**通用 TUI 框架，**不**做动态库，**不**做内核行规程，**不**做 `^Z` 挂起。

它只管一件事：把输入单元序列变成一行可编辑的文本。

## 已知差异

- login 不背历史与 Tab 补全：`read_line_plain` 把 `EditorCaps` 裁到 `plain()`，历史/补全在该
  路径上**编译期可见地不可达**，且 `completions` 永不被调用。
