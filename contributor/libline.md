# libline

用户态行编辑库。把输入单元序列变成一行可编辑的文本。

## 拆分方式

行编辑有两类关注点，可测性不同：

- **编辑语义**：光标移动后缓冲区的状态、退格删除哪个字符、历史如何翻页。是纯函数，可在宿主上
  测试。
- **渲染**：向终端发送什么字节、何时重绘。需要终端，只能在 QEMU 中观察。

`editor.rs` 只做第一类，把 `InputItem` 序列变为缓冲区状态变迁。渲染通过 `EditorHost` trait 由
调用方提供，故编辑器可在宿主上用假 host 驱动，断言缓冲区与渲染调用序列。

## 输入源

本库只依赖一个取得下一个输入单元的窄接口 `InputSource`，其背后是字节流还是事件流由调用方决定。

当前按字节流实现。接入事件流时只需提供另一个 `InputSource` 实现，编辑器本体不需改动。

### 事件源用法

`EventSource` 的两条用法约束：

1. `next_item()` 不是入口。缓冲为空时它立即返回 `WouldBlock`，取数由 `refill()` 负责。
2. `refill()` 返回 `false` 不是输入结束，只表示本轮无新字节。正确写法是继续循环：

```rust
if refill() { continue; }
yield_now();
continue;      // 不 break
```

把 `refill() == false` 当作输入结束而 `break`，程序会静默退出，表现为「打开成功但毫无反应」。

## 边界

本库不是通用界面框架，不做动态库，不做内核行规程，不做 `^Z` 挂起。

它只做一件事：把输入单元序列变成一行可编辑的文本。

## 能力裁剪

login 不提供历史与 Tab 补全：`read_line_plain` 把 `EditorCaps` 裁到 `plain()`，历史与补全在该
路径上不可达，`completions` 永不被调用。
