# evsrcdemo

行编辑库事件源组件的真机验收程序。README 面向使用者；本文件记录组件契约与实测教训。

## 组件路径与诊断形态的分工

evdemo 是诊断形态：手写打开、读取、解析、喂入，刻意绕开事件源组件，用于隔离内核路径问题。
本程序走组件本身。两条路径覆盖的面不同：绕开组件证明内核与设备没问题之后，再验组件就是把
问题定位收敛到库内。组件此前只有宿主单测，真机验收补的是「宿主测试与真机行为一致」这一环。

## 事件源的两条用法契约

初版两条都违反，真机表现为打开成功但毫无反应：

- `next_item()` 不是入口。缓冲空时它立即返回阻塞哨兵，取数由 `refill()` 负责。
- `refill()` 返回 false 不是流结束，只表示「本轮无新字节」。正确循环是：refill 成功则继续处理，
  否则让出 CPU 后继续——绝不退出。

这两条由库的编辑器主循环权威示范。改事件源语义时，先对照主循环的用法。

## 阻塞哨兵的处理

阻塞哨兵（WouldBlock）在本程序中按「无事件」处理：让出 CPU 后重试，不是错误也不是退出条件。
与 consoled 等事件读者的处理纪律一致。
