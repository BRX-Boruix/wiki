# shell

用户态 shell。README 面向使用者；本文件记录实现取舍与改动命令前需要知道的约定。

## 模块依赖单向无环

模块按职责解耦：输出工具、变量表、分词、命令分发、JSON 呈现、行编辑对接。JSON 解析在 libsys，
shell 只负责呈现——解析与呈现分离让树状渲染可以独立改动。新增模块时保持单向依赖，不从底层
模块反向调用。

## 非交互模式与交互模式共用一条执行路径

带参数运行时把整条命令行交给与交互模式相同的执行函数，退出码即该行命令的退出状态。系统初始化
阶段用它跑自检，因此「外部程序怎么被 shell 执行」只有一条真实路径——验收也走这一条。

## 管道的实现顺序

管道系统调用先由演示命令验证（自己 create、write、read 完整走一遍），`|` 语法在语法层落地：
`|` 是保留分隔符，出现即按管道执行，先于单命令分发。实现走 `dup2` 把前一段的输出端接到后一段
的输入端。两处改动都要记住语义约定：**顺序非并发**——每段跑完再跑下一段，依赖内核管道缓冲
无界来保证任意大的中间数据不阻塞。若把内核缓冲改回有界，顺序模型会产生死锁，两处必须一起
评估。多段管道的回滚路径必须完整：中途建管道失败要关闭全部已建端，否则 fd 泄漏。

## 重定向的实现

`>`、`>>`、`<` 统一由重定向剥离与安装两层完成：先从词表剥出重定向（操作符必须是独立词），执行
时用 `dup2` 安装、结束还原。shell 自身的 stdio 备份在高位预留槽，管道与重定向各用一组备份槽，
两层嵌套时还原顺序相反。`$?` 在分词层展开，读的是环境模块记录的上一条状态——管道返回首个
非零段的退出状态。

## Ctrl+C 的两条路径

空闲提示符处按 Ctrl+C：此刻没有前台子进程，shell 只作废当前行，不发信号。前台子进程运行期间
按 Ctrl+C：shell 在等待循环里探查中断并把信号发给前台进程——注意探查读的是非阻塞键入，读到的
非 0x03 字节属于子进程，绝不消费。两处合起来才是完整的「随时可打断」。改行编辑或前台等待
逻辑时，两边都要照顾。

## 收尸与终端输出

后台作业的输出与退出状态由 shell 收集；前台子进程运行中，shell 必须继续读键盘，否则按键无人
消费。等待采用分片超时轮询：每次等待一个固定超时片，超时后探查一次键入再继续等——这是键盘
响应与收尸之间的平衡。内核在「系统内无其他可运行进程」时会拒绝阻塞等待（WouldBlock），重试
前先让出，这不是忙等，是内核诚实语义的正确用法。

## 提示符归属

提示符内容（用户名、当前目录）属 shell，由宿主层提供给行编辑组件；编辑器只管重绘，不知道
提示符长什么样。家目录显示为 `~`。「什么内容」与「怎么画」分离。
