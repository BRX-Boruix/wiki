# coreutils

基础命令集（规划中）。README 面向使用者；本文件记录规划取舍。

## 为什么仓库是空的

内容尚未落地，所以不假装它已经存在。README 中的每一项都以「计划」标注；仓库不被任何构建脚本
引用。状态变化时先改 README。

## 内建与外部的分工

shell 的内建命令覆盖常用路径（零派生开销）；独立的外部命令覆盖「可单独替换、可在 shell 之外
使用」的场景。两者并存是有意的：内建不是外部命令的前置条件，外部命令也不谋求替代内建。
行为以 POSIX 惯例为基准，差异在各自的 README 中如实声明。

## 依赖选择

命令基于 libc（标准 C 接口）加 libsys（系统调用封装）。基于 libc 是刻意的：这是 C 程序在
本系统上的标准路径，命令集同时充当 libc 的真实消费者。
