# selftest

按需自检宿主。README 面向使用者；本文件记录组织取舍与改动测试组前需要知道的约定。

## 为什么自检离开了开机序列

自检是「机器跑给人看」的负载，没有实时观察价值，却让 shell 迟到数分钟（音频流实测每段数十秒）。
开机必须直达 shell，自检整体迁入本程序，由 shell 命令按需拉起。判定看输出行，退出码不承载信息。

## 分组参数读 argv[0]

参数实际落在 argv[0]：内核 exec 路径把命令行作为整条 argv[0] 传入，argc 恒为 1。旧实现读
argv[1]，结果分组过滤从未生效——`selftest thread` 一直在跑全量。现读 argv[0]，空参视为全量，
启动行回显实际生效的组名以便核对。

## 各组的构成

- quick：信号（动作、投递、处理函数、sigreturn）、C 库核心（分配、字符串、格式化、转换、时间）、
  shell 路径（以不同命令行拉起非交互 shell，覆盖三类装载结果）、账户查询独立进程验收。
- thread：多线程演示、C pthread 系列与基准、fork 往返——全部经真实 exec 拉起并收尸。
- audio：阻塞唤醒往返（consumer/producer 两进程）、播放程序的正例与负例。
- 风暴（仅全量）：跨核 spawn 加终止的多轮循环，回归跨核终止缺陷。

## 拉起与收尸纪律

所有子项都经 exec_path 真实拉起、waitpid 收尸。旧实现只拉起不收尸，五个非交互 shell 全部滞留
存活。缺失的程序按「非致命」处理：打印拉起失败，不中断其余项。

## SKIP 与 FAIL 的区分

音频往返需要独占消费者槽。开机序列里它在硬件驱动之前运行所以能成功；在本程序里跑时槽已被占。
该形态是真实约束而非回归：先尝试，得到「设备忙」时如实打印 SKIP。把已知约束报成失败会淹没
真正的回归。
